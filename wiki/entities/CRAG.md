# CRAG (Collaborative Retrieval Augmented Generation)

The **CRAG** framework is a modular, pipeline-based Conversational Recommender System (CRS) that couples Large Language Models with a Collaborative Filtering database. It is designed to run in real-time dialog environments.

---

## 1. LLM-based Entity Link

The Entity Link module bridges the semantic gap between free-form natural language utterances ($s_t$) and structured database item indices ($\mathcal{I}$).

### 1.1. LLM-based Entity Extraction
*   **Inputs:** 
    *   Utterance ($s_t$)
    *   Task-specific prompt ($T_e$)
    *   Batch formatting instruction ($F_e$) forcing responses into: `[item]<sep>[attitude]`, with delimiter `<sep> = "####"`.
*   **Process:** The LLM identifies items mentioned by the user and assigns an ordinal attitude score $a_{t,j} \in \{-2, -1, 0, 1, 2\}$, mapping to `{very negative, negative, neutral, positive, very positive}`.
*   **Output:** The raw item-attitude set $\mathcal{I}^{raw}_t = \{(i^{raw}_{t,j}, a_{t,j})\}_j$.

### 1.2. Bi-level Match and Reflection
*   **Inputs:** Raw strings $i^{raw}_{t,j}$.
*   **Fuzzy Matching:** 
    1.  **Character-level match ($\mathcal{I}^{char}_t$):** Resolves typos by evaluating raw character/edit-distance overlaps against the item database.
    2.  **Word-level match ($\mathcal{I}^{word}_t$):** Links abbreviations (e.g., `"Star Wars 1"`) to full database titles (e.g., `"Star Wars: Episode I - The Phantom Menace"`).
*   **LLM Reflection:** If there is a disagreement between $\mathcal{I}^{char}_t$ and $\mathcal{I}^{word}_t$, the LLM is prompted with the dialogue context ($s_t$) to resolve the discrepancy using the format `[matched_item]####[method]`, where `method` $\in$ `{char, word, both, none}`.
*   **Output:** Standardized, verified item set $\mathcal{I}^{ref}_t \subset \mathcal{I}$.

---

## 2. Context-Aware Collaborative Retrieval

This stage retrieves behavioral recommendation candidates based on the session's positive items, then filters out contextually mismatched suggestions.

### 2.1. Query Rewrite
*   **Inputs:** Unified session history $C_{:k-1}$ and verified entities $\{\mathcal{I}^{ref}_1, \dots, \mathcal{I}^{ref}_{k-1}\}$.
*   **Process:** Filter out neutral and negative items (attitude $\le 0$). The remaining positive items are aggregated to construct a binary multi-hot history vector:
    $$\mathbf{r}_k \in \{0,1\}^{|\mathcal{I}|}$$
    Where $\mathbf{r}_{k,i} = 1$ if item $i$ was mentioned positively, and $0$ otherwise.

### 2.2. Collaborative Retrieval (EASE)
*   **Formula:** Raw collaborative scores are generated by projecting the history vector $\mathbf{r}_k$ through the pre-trained asymmetric EASE weight matrix $\mathbf{W} \in \mathbb{R}^{|\mathcal{I}| \times |\mathcal{Q}|}$ (where $|\mathcal{I}|$ is the database size and $|\mathcal{Q}|$ is the recommendable catalog size):
    $$\text{Scores} = \mathbf{r}_k^T \mathbf{W}$$
*   **Output:** The top-$K$ scoring items are retrieved to form the candidate set:
    $$\mathcal{I}^{CR}_k = \text{Top}_K(\mathbf{r}_k^T \mathbf{W})$$

### 2.3. Context-Aware Reflection
*   **Problem:** CF retrieval is context-blind and might retrieve items that align behaviorally but violate explicit conversational constraints (e.g., suggesting English crime movies when the user specifically requested Portuguese crime movies).
*   **Process:** The LLM is prompted with the conversation history $C_{:k-1}$ and the candidate set $\mathcal{I}^{CR}_k$. It performs a binary contextual relevance check for each candidate using the format `[item]####[relevance]`, where `relevance` $\in$ `{0, 1}`.
*   **Output:** The context-filtered collaborative retrieval set:
    $$\mathcal{I}^{aug}_k = \{i \in \mathcal{I}^{CR}_k \mid \text{relevance}_i = 1\}$$

---

## 3. Recommendation Generation and Post-Processing

The generation phase integrates the filtered collaborative suggestions and resolves position/selection bias in the LLM's response.

### 3.1. Collaborative Query Augmentation
*   $\mathcal{I}^{aug}_k$ is formatted as a semicolon-separated string of items: $I^{aug}_{s,k}$.
*   The prompt is augmented with $I^{aug}_{s,k}$ along with a pretext indicating collaborative behavior (e.g., *"Below are items other users tend to interact with given the positive items mentioned in the dialogue..."*).

### 3.2. Reflect-and-Rerank
*   **LLM Bias:** Because the collaborative items $I^{aug}_{s,k}$ are directly in the prompt, the LLM's attention heads suffer from positional/copy bias, often lazily replicating $I^{aug}_{s,k}$ at the very top of the generated recommendation list $\mathcal{I}^{rec}_k$.
*   **Reranking Solution:** The LLM is prompted to assign ordinal utility scores $s_i \in \{-2, -1, 0, 1, 2\}$ to each recommended item in $\mathcal{I}^{rec}_k$ based on how well it fits the conversational context $C_{:k-1}$, returning the format `[item]####[score]`.
*   **Output:** The final ranked list $\mathcal{I}^{r\&r}_k$ sorted descendingly by the assigned scores.

---

## 4. Handling Conversations without Item Mentions

If the user initiates a conversation without mentioning any specific items (e.g., *"I'm in the mood for a scary ghost movie set in a school"*):
1.  The LLM is prompted to infer and generate a set of potential starter items based on the semantic description in $C_{:k-1}$.
2.  These inferred items are mapped to the database $\mathcal{I}$ using the Entity Link pipeline.
3.  The mapped items are treated as $\mathcal{I}^{q}_k$ (the positive history vector), and the remaining Collaborative Retrieval and Generation steps proceed identically.

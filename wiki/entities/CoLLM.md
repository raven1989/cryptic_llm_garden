# CoLLM (Collaborative Large Language Model)

**CoLLM** is an aligned multimodal-style LLM recommendation framework. It treats collaborative filtering (CF) behavioral data as an independent modality, encoding user-item co-occurrence signals using low-rank traditional models and aligning them with a frozen LLM's text-token embedding space using an MLP mapping layer.

---

## 1. Prompt Construction & Templates

CoLLM utilizes fixed prompt templates containing both natural language semantic contexts and structural ID placeholders.

*   **Prompt Template:**
    $$\text{Prompt} = \texttt{\#Question: A user has given high ratings to the following items: } \langle\text{HisItemTitleList}\rangle \texttt{.}$$
    $$\text{Additionally, we have information about the user\x27s preferences encoded in the feature } \langle\text{UserID}\rangle \texttt{.}$$
    $$\text{Using all available information, make a prediction about whether the user would enjoy the}$$
    $$\text{item titled } \langle\text{TargetItemTitle}\rangle \texttt{ with the feature } \langle\text{TargetItemID}\rangle\texttt{? Answer with "Yes" or "No". \#Answer: }$$

*   **Variables:**
    *   $\langle\text{HisItemTitleList}\rangle$: Comma-separated list of historical movie titles.
    *   $\langle\text{TargetItemTitle}\rangle$: Target movie title to predict.
    *   $\langle\text{UserID}\rangle$: A virtual placeholder representing the active user (e.g., `[USER_TOK]`).
    *   $\langle\text{TargetItemID}\rangle$: A virtual placeholder representing the target item (e.g., `[ITEM_TOK]`).

---

## 2. Hybrid Encoding and CIE Alignment Module

The hybrid encoding stage combines standard LLM vocabulary lookups with mapped collaborative vector injections.

### 2.1. Token Sequence
For a sample $(u, i, y)$, the input text is tokenized into sequence $P$:
$$P = [t_1, t_2, \dots, t_k, u, t_{k+1}, \dots, i, \dots, t_K]$$
Where standard words map to $t_k$, and $u$ and $i$ represent the singular virtual placeholder tokens for the user and item.

### 2.2. Embedding Interception
The output embedding sequence $E$ is constructed as:
$$E = [\mathbf{e}_{t_1}, \dots, \mathbf{e}_{t_k}, \mathbf{e}_u, \mathbf{e}_{t_{k+1}}, \dots, \mathbf{e}_i, \dots, \mathbf{e}_{t_K}]$$

Where:
*   $\mathbf{e}_{t_k} \in \mathbb{R}^{1 \times d_2}$ represents standard LLM word embeddings retrieved via standard lookup table: $\mathbf{e}_{t_k} = \text{Embedding}_{LLM}(t_k)$.
*   $\mathbf{e}_u \in \mathbb{R}^{1 \times d_2}$ and $\mathbf{e}_i \in \mathbb{R}^{1 \times d_2}$ represent continuous collaborative embeddings generated by the **Collaborative Information Encoding (CIE)** module:

$$\mathbf{e}_u = g_\phi(\mathbf{u}) \quad \text{where} \quad \mathbf{u} = f_\psi(u; \mathcal{D}) \in \mathbb{R}^{1 \times d_1}$$
$$\mathbf{e}_i = g_\phi(\mathbf{i}) \quad \text{where} \quad \mathbf{i} = f_\psi(i; \mathcal{D}) \in \mathbb{R}^{1 \times d_1}$$

### 2.3. CIE Mathematical Components:
*   **$f_\psi(\cdot)$ (Base CF Encoder):** A pre-trained traditional collaborative recommender (e.g., Matrix Factorization, LightGCN, or DIN) producing low-rank user/item factors of dimension $d_1$.
*   **$g_\phi(\cdot)$ (MLP Alignment Layer):** A Multilayer Perceptron mapping vectors from the low-rank collaborative latent space ($d_1$) directly to the LLM token embedding space ($d_2$, typically `4096`).

---

## 3. Two-Step Tuning Strategy

To stabilize convergence and prevent the collaborative embeddings from degrading the LLM's cold-start generalization capabilities, training is bifurcated into two separate phases:

```text
Phase 1: Semantic Task Learning (Tuning LoRA)
  Inputs: Text-only prompts (Stripping ID placeholder fields)
  Frozen: Base LLM and Embedding Layers
  Trainable: LoRA adapters (Rank R=16, Alpha a=32) on all linear layers
  Loss: Binary Cross-Entropy (BCE) over Target Label y ("Yes"/"No")

Phase 2: Behavioral Alignment (Tuning CIE)
  Inputs: Aligned prompts (Restoring ID placeholder fields)
  Frozen: Base LLM, Embedding Layers, and Phase-1 LoRA adapters
  Trainable: MLP Mapping parameters (phi) and Base CF weights (psi)
  Loss: BCE over Target Label y ("Yes"/"No")
```

### 3.1. Phase 1 Objective:
$$\hat{\Theta}^{\prime} = \text{argmin}_{\Theta^{\prime}} \sum_{(u,i,y) \in \mathcal{D}} \ell\left( h_{\hat{\Theta} + \Theta^{\prime}}(E_t), y \right)$$
Teach the LLM how to parse the recommendation prompt and match semantics in the high-dimensional latent token space.

### 3.2. Phase 2 Objective:
$$\hat{\phi}, \hat{\psi} = \text{argmin}_{\phi, \psi} \sum_{(u,i,y) \in \mathcal{D}} \ell\left( h_{\hat{\Theta} + \hat{\Theta}^{\prime}}(E), y \right)$$
Train only the mapping layer to project pre-trained collaborative features into the LLM's frozen semantic space, aligning user behaviors with semantic concepts.

## 4. Ablation Analysis: CIE vs "w/ UI-token"

A key design validation in CoLLM is the comparison between the CIE projection module and the direct vocabulary mapping (`w/ UI-token`):

1.  **`w/ UI-token` (Naive Direct Vocabulary Mapping):**
    *   Adds a unique textual ID token for every user and item directly into the LLM's tokenizer vocabulary.
    *   Trains their embedding weights from scratch inside the LLM alongside standard words.
2.  **Why Direct Mapping Fails (`w/ UI-token` < `w/o CIE`):**
    *   **Vocabulary Redundancy:** Introducing thousands of individual user/item tokens into the LLM's vocabulary increases tokenization redundancy and drops the model's overall information compression rate, degrading general reasoning.
    *   **Lack of Collaborative Priors:** Direct vocabulary embeddings are initialized arbitrarily and share no structural information.
3.  **Why CoLLM-CIE Projection Succeeds:**
    *   By using a pre-trained traditional CF model (like LightGCN), the collaborative representations $\mathbf{u}$ and $\mathbf{i}$ are constrained by **low-rank graph priors** (e.g., neighborhood co-consumption signals).
    *   The MLP mapping layer $g_\phi$ simply acts as a coordinate translator, injecting these structured, highly compressed co-occurrence signals directly into the LLM without bloating the vocabulary.
